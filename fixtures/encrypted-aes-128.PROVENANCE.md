# `encrypted-aes-128.pdf` — provenance and passwords

**Copied 2026-09-03** from `D:\Dev\pdfcer\fixtures\synthetic\encryption\enc-aes-128.pdf`,
byte for byte. It is a **synthetic** fixture generated by the pdfcer project for
its own encryption tests; nothing in it is anybody's document.

| | |
|---|---|
| `/V` | 4 |
| `/R` | 4 |
| key length | 128 |
| cipher | `/AESV2` (AES-128 CBC) |
| **user password** | `userpw` |
| **owner password** | `ownerpw` |

## Why the passwords are written down here, in a public repository

Because they are test data, they are already published in the pdfcer repository's
own `PROVENANCE.md`, and a fixture whose password nobody can find is a fixture
nobody can use. A driven check has to type *something*.

## ★ Why this file was copied rather than referenced in place

`tools/ui-verify`'s checks must run on a clean checkout of **this** repository.
A check reaching into `D:\Dev\pdfcer\fixtures\` would work on this machine and
SKIP everywhere else, and a skip is not red — so the check would quietly stop
being evidence the day the two repositories were checked out separately, which
is the arrangement fold-in produces.

Calibrated checks are allowed to aim at the operator's own drawings in
`D:\Dev\pdfTests\` because their subject genuinely *is* one of his files. This
one's subject is *"an encrypted PDF"*, and any encrypted PDF will do.

## ★★ Why AES-128 and not AES-256

Because `pdfcer-core` refuses `/R` 6 — the revision, not the cipher — and `/R` 6
is what Acrobat X and later write. `/R` 5 AES-256 is readable and is a small
population of real files. `/AESV2` at `/R` 4 is both readable and the shape of
the majority of encrypted PDFs in circulation, so a check aimed at it exercises
the path an operator's own file will take.

⇒ **That refusal is worth knowing about separately**: a `/R` 6 document does not
reach `Status::NeedsPassword` at all. It fails on the encryption *configuration*
before any password is asked for, so it lands in `Status::Unsupported` and the
password prompt never appears — correctly, because no password would help.
