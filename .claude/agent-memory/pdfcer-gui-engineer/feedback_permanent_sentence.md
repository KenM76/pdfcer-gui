A sentence whose truth **expires** belongs in exactly one place, beside the
command that answers it. Never inside a paragraph whose own subject is
finished.

`RESUME.md` carried *"published as `<tag>`, which is the slot he runs"* three
times, in three paragraphs about three different releases. Only one could be
right; the other two read as confident statements of current state and had
been wrong for days.

**Why:** the failure is structural, not carelessness. A paragraph recording
what a release contained is a fact that never changes, so nothing will ever
prompt a revisit — the release it describes is over. A clause about the live
build changes on every publish. Attach the second to the first and it rots
with no event that would catch it. This is the same shape as
[[a-verbatim-quotation-of-another-files-count-goes-stale-invisibly]] and
[[a-limitation-sentence-is-a-citation-with-an-hours-long-shelf-life]], but the
carrier here is a *finished* narrative rather than a figure or a claim about
the engine, which is why no existing guard saw it.

**How to apply:** in a "what shipped" paragraph write *first published in
`<tag>`* and stop. Put the perishable question in the state table as its own
row with its command, and say why the obvious reading is wrong — here, that
the OneDrive slot name carries no version and the rotation alternates, so the
newer slot is 1 on one release and 2 on the next. Watch for the same shape
anywhere a past-tense record reaches for a present-tense clause: *"which is
what he has"*, *"which is still open"*, *"which the engine still lacks"*.
