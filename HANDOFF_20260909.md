## 1. The wobble — what it was, how it was found, what changed

**Symptom, two days old:** the central panel's width oscillated 0.1–0.5 pt on
isolated frames with nothing on screen changing. Five instruments across two
sessions each narrowed it by one container and stopped at "inside egui's
`Panel::show`".

**The instrument that found it** (`egui-shell/src/dock/overflow_probe.rs`): on
any frame where a side's frame rect crosses the window edge, publish every
widget egui registered this pass whose rect also crosses it, by egui id
(`ctx.viewport(|v| v.this_pass.widgets.layers())`). First read, off-screen,
same fixture and layout as the wobbling traces: five widgets, four containers,
one leaf — `[1390.0, 292.7]–[1400.4, 866.0]`, a 10-pt strip on the Comments
pane's right edge, decaying `1400.4 → 1400.1 → 1400.0`. Ten points at the
edge is the scroll bar (`bar_width = 10`); a decay is an animation.

**The mechanism, each part from egui 0.35 source:**

1. `Panel::show` takes its rect back from the frame's content union and, when
   it is wider than `exact_size`, restores the width by moving the INNER edge
   (`min.x = max.x − size`). `exact_size` fixes a width, not a position.
2. `scope_builder` ends by allocating the child's `min_rect()` into its
   parent, so a body's overflow climbed into the side's frame. `set_clip_rect`
   truncates paint, not layout — the comment beside it ("clipped, not
   accommodated") was true of pixels and false of rects.
3. A SOLID `ScrollStyle` has fractional bar use while its bar fades in
   (`show_bars_factor × allocated_width`, cubic-out). The content rect is
   rounded up to whole pixels, `auto_shrink` adopts the rounded width, the
   fraction is added back: `rounded(outer − f·W) + f·W` exceeds the pane by the
   rounding residue on mid-fade frames. Floating bars never do it (boolean
   bar use).

**Reproduced** in `egui-shell/src/dock/scroll_fade_repro.rs` — a right
`Panel::exact_size(320)` with a solid 10-pt `ScrollArea` whose content grows on
frame 5, fixed 60 fps clock: `+0.25` (frame 8), `+0.47` (frame 9), zero
elsewhere. It asserts the overflow so an egui fix turns it red.

**Fixed** in `egui-shell/src/dock/stack.rs` (moved out of `mod.rs`, which the
explanation pushed past R2): bodies draw in `ui.new_child` — never merged —
and the compartment's own rect is allocated in their place. The regression
guard (`overflow_probe.rs` tests) was written against the UNFIXED code first:
`[1080.4 .. 1400.4]`, the trace's line; green after.

**Kept:** `RESIZE_FLOOR_PT` in `fit.rs` (re-documented: source known and gone;
the floor stays because a sub-pixel viewport change is not a resize anyone
made). `overflow_probe` stays as the tripwire. `dock.<side>.body_min` is now
always equal to `.frame` and can go next release.

**RAG:** `D:/dev/rag/egui/a_solid_scrollbar_fading_in_overshoots_its_pane_and_an_exact_size_panel_slides_inward_by_the_excess.md`.
**Memory:** `feedback_when_a_wobble_is_inside_the_framework_list_the_leaves_by_id`.

## 7.1 The engine pin: a bump that was measured, not assumed

The standing rule is to update the engine before every build, because the
engine repo moves fast and a stale pin has already cost eighteen missing
images. It is the right default. It is not a reflex.

`Cargo.lock` pinned `369d4de`. The engine tree's `main` was **two commits
ahead**. The question is not "is it behind" — it is "is the *code* behind":

    git -C D:/Dev/pdfcer diff --stat 369d4de..HEAD

Both commits touch only `docs/` and `.claude/` — librarian filings, nothing
under `crates/`. So the pin is **code-current** and no rebuild was owed. That
is a ten-minute engine rebuild saved, and — more to the point — it is a
*measurement* rather than an assumption in either direction. The rule to carry
forward is not "always bump" and not "check the date"; it is **read the
`diff --stat` from the pin to HEAD and ask whether `crates/` appears**.

`load_anomalies_reach_the_status_bar` — the cheap, no-input half of the

precisely the moment to distrust it. R1 says verify by driving the binary; it

The check has two clauses and they are independent, so each was falsified on

## 7.4 ★★ The second finding: `Session::place` was overruling the viewport

`PDFCER_DIAG_VIEWPORT` sets both the size and the **position** of a launched
window, and the position is what makes an off-screen smoke launch off-screen.
It was being silently discarded: `launch::Session::place` moved every launched
window to desktop `(780, 40)` unconditionally, to dodge the on-screen
keyboard.

The consequence is worse than a wrong pixel: a no-input check whose doc
comment said *"the window is placed off the desktop so it cannot steal focus"*
would have put the window in the middle of the operator's screen while
claiming otherwise — the doc comment and the behaviour disagreeing, with the
doc comment being the thing a future session reads.

`LaunchSpec::place` is the opt-out. It is documented at **both** ends as a
promise that **no pointer event and no keystroke is sent by that launch**.
Do not set it `false` on any check that clicks. The `OFFSCREEN` constant in
`checks/load_anomalies.rs` carries the warning inline:

> ⚠ The position only survives because `launch_quiet` sets `LaunchSpec::place`
> to `false`. The flag was added with this check, 2026-09-09, and the two must
> not be separated.

## 8.4 ★★★ Why `check-stale-blockers.sh` ran green over all of it for three days

**Two independent causes. Either one alone was sufficient.**

**(1) The scope list omitted the canonical file.** `DOCS=(...)` held
`OPERATOR_REQUESTS.md`, `FEATURES.md`, `GUI_ROADMAP.md` — and not
`ENGINE_BACKLOG.md`, the one file whose entire purpose is blocked rows. Nothing
looked wrong: the gate reported OK, the documents it named were real, and the
count of documents scanned added up. The list stays hand-written **on purpose**
(`HANDOFF.md` and `CONTINUE.md` are historical, and a past tick correctly says
"blocked" about the day it was written), so the fix is not automation — it is a
comment at the list telling the next author to add their document in the same
commit.

**(2) ★★ The gate's evidence is an artifact WE write.** The predicate is a
`*CONSUMED*.md` note in `open/` naming the request. That is **correct and must
not change**: a reply that schedules, defers, refuses or merely explains must not
clear a blocker, and only this side knows when a capability has actually been
taken. The gate's own header records an earlier version firing on a **true**
warning and warns that such a failure *"would have had somebody delete a true
warning to make a build go green"*.

The consequence nobody had drawn: **we took all four capabilities and never wrote
the note.** So even with `ENGINE_BACKLOG.md` in scope, the gate would still have
passed.

> **A gate whose evidence is an artifact you author is blind by construction to
> the artifact you forget to author.** Filing the record is not paperwork; it is
> the act that arms the check.

Both notes now exist: `open/done_2026-09-06-markup-style-four-CONSUMED.md` and
`open/done_2026-09-06-text-import-CONSUMED.md`.

## 8.5 ★★ The trap on the other side, found by falsifying the fix

Re-run on the **corrected** files, the gate reported two more hits — and both
were **correct** rows narrating their own history: a ✅ row reading *"THE ⛔ ON
THIS ROW WAS STALE AND IS CORRECTED"*, and a **Reachable** row reading *"this
row was `blocked` for about six hours"*. Both name the request file, because a
correction that erases its own citation cannot be audited.

**A false positive on a correctly-updated row is the same hazard as a false
positive on a true warning, pointing the other way**: the cheapest way to clear
it is to delete the history sentence, and the history sentence is the most
valuable part of a corrected row.

Fixed by reading the **cell-initial** verdict token rather than the whole line —
a row's verdict lives at the start of a cell, so `✅` / `**Reachable` /
`**Consumed` / `**WIRED` / `**UNBLOCKED` settles the row for today and a blocked
token elsewhere is narration. The token list was **measured** out of the four
documents, not invented.

⚠ **The excused count is printed on every run, green ones included.** An
exclusion nobody can see is how a gate quietly narrows its own scope. Currently
**15**; a number that climbs unnoticed is lost coverage, and a number that falls
to zero means the documents stopped using a token.

⬜ **Two limits, stated rather than papered over.** A row genuinely blocked
today whose author begins its verdict cell with a closure token would be
excused — self-contradictory prose that does not exist in these documents, but a
hole, not a proof. And the gate matches a blocked claim and a request filename on
the **same line**, deliberately; the text-import defect lived in a paragraph and
would not have been caught even with the file in scope.
