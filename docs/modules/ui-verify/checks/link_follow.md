# `ui-verify/checks/link_follow`

**Clicking a `/Link`** — the two checks for a capability that did not exist
in this shell at all until 2026-09-01.

# The operator's question, and the honest answer at the time

> *"does a clickable table of contents work?"*

No — and not in the ordinary way features fail. **There was no
link-following code path anywhere in the shell.** Clicking a `/Link` did
nothing, nothing on screen suggested it would, and a drawing package whose
whole navigation is a hyperlinked contents sheet behaved like a stack of
loose pages.

It was not a shell defect either: a link's destination could not be **read**.
`Annotation::action_type` is the `/S` name and nothing else, by an explicit
engine decision that is right for `list-annotations` and useless to a viewer.
`outline::DestinationReader` and `annot::page_link_destinations` shipped in
answer to the request; `crate::canvas::links` is the shell half and this file
is what makes it a shipped capability rather than a written one.

# Why there are TWO checks and why the second one is the important one

`Destination` has five variants and only one navigates. The failure this
feature is most likely to ship is not "links do not work" — that is loud and
somebody reports it in a minute. It is **a viewer that treats all five as
navigable**, resolves the four it cannot perform to a defaulted page 0, and
sends the operator confidently to the front of the document.

That failure has no symptom. The cursor changes, the click lands, a page is
shown. Nobody files it as a bug; they conclude the document's links are
wrong. So:

| check | subject | what it would catch |
|---|---|---|
| [`ALinkGoesToThePageItNames`] | a `/GoTo` that resolves | the capability being absent, or aiming at the wrong page |
| [`ALinkItCannotFollowSaysSo`] | a `/URI` | **a link that cannot be performed being performed anyway** |

The second asserts a **conjunction of an absence and a presence**: the
page did **not** change, *and* a sentence was drawn. Either alone is
satisfiable by a wrong build — a shell that ignored the click entirely passes
the first half, and one that navigated *and* explained itself passes the
second.

# The fixtures, and the property that makes them worth committing

`fixtures/goto-actions.pdf` and `fixtures/non-navigation-links.pdf`, copied
from the engine's `fixtures/synthetic/links/` where they are generated by
`tools/gen-link-fixtures.py` and documented in that folder's
`PROVENANCE.md`. Both are synthetic, both are about a kilobyte.

**No link in either one targets page 1**, and that is deliberate — the
engine's own note asks for it to be copied:

> *"a destination resolver's most likely defect is returning a defaulted `0`,
> and a fixture whose links all point at page 1 passes against an
> implementation that resolved nothing at all."*

`goto-actions.pdf` has four links on page 1 at known rectangles, targeting
pages 2, 3, 4 and 2 with `Fit`, `XYZ`, `FitH` and `FitR` respectively. This
check drives the **third** — page 4, the furthest target — for the same
reason: an off-by-one or a defaulted index cannot reach it by accident.

# Why it clicks in Read

Because that is where following happens, and where the operator asked for it.
In Edit a `/Link` is an annotation like any other and a click **selects** it,
so that it can be moved, resized or deleted — see `canvas::links`' header on
why that split is the conventional one and not an invention. Read is also the
shell's default mode, so no mode click is needed and one fewer thing can go
wrong before the subject is reached.

# Every way these report SKIP

No binary, `--no-input`, no diagnostic channel, no canvas rect to aim
against, or a fixture that is not where it should be. None of those is a
pass, and each says which it was.
