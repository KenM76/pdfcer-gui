# `ui-verify/checks/off_page_marquee`

`a_band_dragged_into_the_margin_reaches_an_object_off_the_page` — **the
object he dropped over the edge and could not get back.**

# The report


> *"we should be able to select things offside of the page, especially since
> I sometimes drop objects there, and when I do I can't get them back."*

Half of that shipped the same day: **Select All** takes every object on the
sheet including the ones outside its boundary, so a dropped object can be
grabbed and dragged home. The other half — *"drag a box in the margin"*,
which is the gesture anybody would actually reach for — did not, and was
tracked as the same defect as O88: the band only took what it completely
surrounded.


# Why the assertion is `hits == 1` and why that is airtight

`fixtures/off-page-object.pdf` is a 200 × 200 page with exactly **two**
filled squares and nothing else:

| | where | on the page? |
|---|---|---|
| **A** | x 40–100, y 40–100 | yes |
| **B** | x −160 – −40, y 100–140 | **no — entirely left of the media box** |

The band runs from `(160, 170)` — blank paper in the top-right — leftward
and downward to `(−100, 120)`, so it covers x −100…160, y 120…170.

* It **misses A entirely**: A's top edge is y = 100 and the band's bottom is
  y = 120.
* It **touches B** — x −100…−40 and y 120…140 are inside both.
* It **cannot enclose B**, because B reaches x = −160 and the band stops at
  x = −100. That is deliberate: an enclosing band would satisfy this check
  for the wrong reason and it would stop discriminating between the two
  modes.
* Nothing else exists anywhere on that page.

⇒ **One hit can only be B**, so the count alone proves the band reached off
the page. No index, no ordering assumption, no kind census needed.

And zero hits is the previous behaviour exactly: an `Enclosed` band over
that rect surrounds nothing at all.

# What had to be added to the harness, and why it is narrow

`CanvasMapping::doc_to_window` **refuses every point outside the media box**,
and that refusal is right for every other caller — a point off the page is
almost always a check aiming at the wrong sheet. This check needs to aim into
the grey margin on purpose, so it uses
[`CanvasMapping::doc_to_window_off_page`], a separately named entry point
that relaxes the page bound and **keeps the canvas bound**. A caller has to
say the words.

# Why a synthetic fixture rather than his drawing

Because *"an object off the page"* is a property no document in the tree has,
and one that cannot be produced by accident. The fixture is 485 bytes of
hand-written PDF syntax, uncompressed and readable, generated by the snippet
recorded in its own commit. His sheets are the right subject for *quality*
questions; this is a *geometry* question with an exact answer.

# Every way this reports SKIP

No binary, `--no-input`, no diagnostic channel, no page on screen, the Select
tool unreachable from the ribbon, or **not enough grey margin on screen to
reach x = −100** — which is a property of the window size on the day and is
reported as a skip that names the geometry, never as a pass.
