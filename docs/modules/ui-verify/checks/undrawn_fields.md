# `ui-verify/checks/undrawn_fields`

`a_form_without_drawn_values_draws_and_clicks` — **a form that asks the
reader to draw its values shows them, opens on a click, and is not modified
by being opened** — `OPERATOR_REQUESTS.md` O327.

# The fixture

`fixtures/need-appearances-fields.pdf`, generated by its `PROVENANCE.py`:
three `/Tx` fields with no `/AP`, `/NeedAppearances true`, `/V (Hello)` and
`/MK /BC [0 0 1]`; two at `0 Tf` (auto-size), one at `12 Tf`. `--pdf` runs
the same assertions on any such form.

# The assertions, in order

1. **On the canvas.** At least three `form-box kind=text` lines.
2. **Drawn.** In a screenshot, each box (widened 2 px) holds at least
   `MIN_INK` dark pixels (the value) and `MIN_BLUE` saturated-blue pixels
   (the border). Pixels are the only oracle: the trace cannot tell a drawn
   field from an empty one.
3. **Disclosed honestly.** The panel's `forms-canvas-note` line exists and
   does not say the fields are "not drawn on the page".
4. **Not modified.** Ctrl+S (always enabled) writes the document; the saved
   bytes must equal the opened bytes. A drawing that went into the document
   instead of onto the screen changes them.
5. **Clickable.** A click at the first box's centre traces `form-focus` naming
   that field.

# Falsification

- The published build before this change: FAIL at 1 (0 boxes).
- Planted, one at a time: the renderer handed the real session (FAIL at 2,
  0 ink); the old note text (FAIL at 3); a `/Title` edit on open (FAIL at 4,
  1310 bytes saved for 1149); the click point's y not flipped (FAIL at 5, no
  `form-focus`).

# Known limit

On a document whose form is not on page 0 the check SKIPs: the page
geometry comes from page 0.
